# The House, Lizzy and the formula: Brennan's as "my restaurant" across the three craft wings

## Context

The owner has been hired at Brennan's (417 Royal Street, New Orleans) and wants the suite to carry Brennan's as their restaurant: every menu item with the 10/20/45-second server lines, the by-the-glass list with its pairings, the cocktails, the pronunciations, the guest conversations, and drills over all of it, at every position (servers and cooks in the World Table, bartenders in the Ledger, sommeliers in the Codex). The 51-page server guide (`Brennans_Info.pdf`, menus read 26 Sep 2026) is the menu source. The same machinery must work for any user and their restaurant through the Maître d', who becomes Lizzy: a whole persona with a voice.

Today each wing keeps its own venue record (My Menu dishes in the Table's IndexedDB, My Bar in the Ledger's `bartenders-ledger-v1`, Our Wine List in the Codex's `codexStats`), nothing says what restaurant they belong to, the Maître d' writes five short lines (`say, guest, why, pairs, origin`) and reads menus, and only `/menu/quiz` drills house content. This plan makes one House, gives Lizzy her voice and eight new tasks, adopts the guide's formula as the standard for every house, builds the Brennan's pack through the same pipeline, and adds the four drills.

## The owner's decisions (3 Oct 2026, final)
1. **Lizzy**: a whole persona behind the Maître d' door (the button may still say "The Maître d'"): British woman, Anthony Bourdain's attitude with the swearing kept, master chef, master bartender and master sommelier, expert world traveller, sage wisdom and famous historical quotes from a sourced, verified bank only (she may paraphrase and say so). Thorough, in-depth, personal, special. Her hard rules in code stay. A per-device "keep it clean" switch, default her full voice.
2. **One House** shared across the three craft wings; each reads and drills its part; anyone must be able to train to mastery at every position.
3. **A list of houses, one current**; packs import as new houses and never overwrite one unless the person says so.
4. **Other users** build their house through Lizzy reading their menus (paste, photo, PDF, link) with their own key, by the same steps the Brennan's pack takes, made user-friendly; hand editing stays; a finished house exports as a pack; a pack imports with no key.
5. **The Brennan's pack** is built in this project by Claude Code (no paid key) through the same pipeline and validators, committed as a data file, import-only, never advertised in the UI.
6. **The full formula** is the standard for every item in every house: five parts; 10/20/45-second lines (25/50/110 words); the pairing block from the house's own list; pronunciation; origin; service note; plus the house card, tastings, lexicon, scenarios, mix-ups, must-knows; prices as printed with a "menus read on" date.
7. **Allergens**: service notes come in as the person's own words marked "confirm at lineup"; allergen boxes stay empty and unchecked; Lizzy never writes allergen content.
8. **Drills**: Say it back graded by Lizzy (key); offline flashcards and tests; Guest at the table role-play (key); offline pairing drill.
9. **Live menus**: proceed from the PDF plus web search.
10. **Publishing**: push straight to main as each piece is validated, from this session.
11. **Caps**: "Up all caches and limits." Every ceiling that constrains the House or Lizzy is raised with a reason beside it; the Ledger's 365 cocktails is no longer a ceiling (answers the handoff's open question 3).

## The approach (the judged design, with four overrides)

A design panel (three architects, three judges, a synthesis, two critics, a revision; full text at `/tmp/claude-0/-home-user-zpullen98-gif-github-io/09201eae-82ec-5cba-9316-4d6cf5955e5e/scratchpad/design-plan.md`, to be committed as `worldtable/docs/house-and-lizzy-design.md` in piece 0) chose **wing-native**: one House record per venue, authored once as TypeScript under `worldtable/src/lib/house/`, bundled by the Table and ported to `static/shared/oot-house.js` for the two vanilla wings by the same `port-desk.mjs` discipline (`tools/port-core.mjs` lifted out, `tools/port-house.mjs`, `tools/check-port-house.mjs`). Each wing's own list stays a projection of the House filled only through that wing's own door (`addDish`, `saveBarRecord`, `cellarSanitize`), so every existing normaliser, merge, SRS key and "kept means `by === 'person'`" gate holds. The formula rides as marks in the wings' unchanged `{value, by, ts}` shape. Lizzy lives in `oot-maitre.js`. Drills live where each wing drills. A shared vanilla `oot-house-ui.js` gives the Ledger and the Codex one read-and-keep screen so a bartender or sommelier reads and keeps everything she writes without the Table.

Overrides of the design, by the owner's decisions:
- **Storage is IndexedDB, not localStorage.** Database `oot-house`, store `houses` (one record per house, key = house id), with the small synchronous index in localStorage `oot-houses-v1` `{v, current, list:[{id, name, ts, bytes, began}]}`. Reason: "up all limits"; a 512 KB localStorage slot beside `codexStats` and `bartenders-ledger-v1` on Safari's ~5 MB origin quota was the design's own first risk. Per-house cap `HOUSE_MAX_BYTES = 8 MB` (a refusal names the pack export as the way out), no cross-house warning. Each wing's projection is still read synchronously at boot (unchanged), and the house arrives asynchronously: the Ledger's boot is already an async IIFE (`js/app.js:1028`), codex27 wraps `render` and re-renders once the house loads, the Table syncs in `hydrate()`. Every store function takes an adapter `{get, put, remove, list}`; the Node checks use a Map-backed one.
- **Own-house drills are free in all three wings.** No house global joins `shared/oot-locks.js`; the Ledger's house drill modes are reached from the Menu tab's "Drill what is on it" panel (free). With `free: true` this changes nothing on the live site today; when a subscription returns it is one deliberate line per wing. Consequence: `oot-locks.js` is untouched, so Light and Almanac need no carry-forward.
- **The quote bank ships verified, not empty.** Candidates are found and verified here by the same adversarial pipeline the suite uses for First Light (two independent search-backed checks per quote, the located passage recorded); `tools/quotes/candidates.json` keeps the URL and evidence (never shipped); `checkedBy: 'claude-code'` with the evidence is sufficient to ship; the owner may untick any entry. `check-quotes.mjs` still refuses an entry with no evidence, a `who` outside the closed `PEOPLE` list, a duplicate id, a dash, a URL in the shipped file, or text over 40 words; the cap of 60 entries goes (no cap; the block is sorted by id and cached).
- **Wines carry the three timed lines and five parts too**, so Say it back is one drill for every kind. `WINE_PARTS = { main: 'grape and region', technique: 'how it is made', sauce: 'the profile', sides: 'what it goes with', taste: 'how it tastes' }`; `GRADE_SCHEMA` is one schema over `DISH_PARTS | COCKTAIL_PARTS | WINE_PARTS`.

Decisions on the design's open questions: the implicit house is named "My house" and renamed from the switcher (no extra dialog); the clean switch needs no device lock; Brennan's house-card facts come from the guide's must-knows; the two guide discrepancies (house Champagne $28 vs $30; Rare 2012 vs 2013) are written into the two wines' service notes for the owner to settle; the Light and Almanac shells stay untouched.

## A. The House data model (`worldtable/src/lib/house/house-schema.ts`)

Every comment in these modules ships inside `oot-house.js` (`port-desk.mjs` keeps comments and `assertClean` refuses any dash spelling and non-ASCII regex literals), so comments are dash-free and regexes ASCII.

```ts
export const HOUSE_FORMAT = 'oot-house'; export const HOUSE_SCHEMA_VERSION = 1;
export const HOUSE_INDEX_KEY = 'oot-houses-v1';        // localStorage, small, synchronous
export const HOUSE_DB = 'oot-house'; export const HOUSE_STORE = 'houses';   // IndexedDB
export const HOUSE_MAX_BYTES = 8 * 1024 * 1024;
export const LINE_CAPS = { s10: 25, s20: 50, s45: 110 } as const;
export const PRINCIPLES = ['acid','fat','weight','sweet','heat','tannin','salt','bridge','method'] as const;
export const DISH_PARTS = { main:'main ingredient', technique:'technique', sauce:'sauce and key flavours', sides:'accompaniments', taste:'how it tastes' } as const;
export const COCKTAIL_PARTS = { main:'the spirit', technique:'the build', sauce:'modifiers and key flavours', sides:'glass and garnish', taste:'how it tastes' } as const;
export const WINE_PARTS = { main:'grape and region', technique:'how it is made', sauce:'the profile', sides:'what it goes with', taste:'how it tastes' } as const;
export const BUILD_STEPS = ['card','menus','filed','formula','pairings','wines','lexicon','scenarios'] as const;

export interface Mark<T = string> { value: T; by: 'maitre' | 'person'; ts: number; model?: string }   // the wings' mark, unchanged
export interface Note { q: string; a: string; ts: number; model?: string }
export interface FormulaParts { main: string; technique: string; sauce: string; sides: string; taste: string }
export interface Lines { s10: string; s20: string; s45: string }
export interface Pairing { wineId: string; why: string; sayIt: string; whyThisWine: string; palate: string; principles: Principle[]; secondId: string; secondWhy: string; stepUp: string; serve: string; avoid: string; zeroProofId: string; zeroProofWhy: string }
interface ItemBase { id: string; house: string; name: string; section: string; meals: string[]; price: string; prices: Array<{meal: string; printed: string}>;
  say?: Mark; guest?: Mark; why?: Mark; pairs?: Mark; origin?: Mark; kept?: Note[]; parts?: Mark<FormulaParts>; lines?: Mark<Lines>;
  serviceNote: string;   // a PERSON's words, never written by Lizzy, House-only
  ts: number }
export interface HouseDish extends ItemBase { kind:'dish'; description: string; ingredients: string[]; marks: string[]; ingredientsNamed?: Mark<string[]>; pairing?: Mark<Pairing>; signature: boolean }
export interface HouseWine extends ItemBase { kind:'wine'; producer: string; wine: string; vintage: string; region: string; grapes: string[]; style: string; glass: string; bottle: string; pours: string[]; profile?: Mark; goesWith?: Mark; firstPickIds?: Mark<string[]>; serve?: Mark }
export interface HouseCocktail extends ItemBase { kind:'cocktail'; spec: string[]; method: string; glass: string; garnish: string; note: string; family: string; spirit: string; zeroProof: boolean; upsells?: Mark<string[]>; ingredientsNamed?: Mark<string[]> }
export interface Tasting { id; name; price; meal; includesDrinks: boolean; courses: Array<{n; label; dishIds: string[]; pourId; pourText}>; note; ts }
export interface LexiconTerm { id; term; say?: Mark; toGuest?: Mark; itemIds: string[]; ts }
export interface Scenario { id; title; guest; you?: Mark; principle?: Mark; itemIds: string[]; ts }
export interface MixUp { id; aId; bId; difference?: Mark; ask?: Mark; ts }
export interface MustKnow { id; title; body?: Mark; ts }
export interface House { format:'oot-house'; version: 1; id; name; address; phone; site; meals: Array<{name; days; hours}>; history?: Mark; dressCode; menusReadOn; sources: Array<{title; url; readOn}>;
  tastings: Tasting[]; dishes: HouseDish[]; wines: HouseWine[]; cocktails: HouseCocktail[]; lexicon: LexiconTerm[]; scenarios: Scenario[]; mixUps: MixUp[]; mustKnows: MustKnow[];
  removed: Record<string, number>; build: Partial<Record<BuildStep, number>>; began: 'pack'|'desk'|'hand'; createdAt; lastWrite; pack?: { id; builtBy; builtAt; version } }
```
No allergen field anywhere (`allergens` and `allergensCheckedAt` stay Table-only); `normaliseHouse` runs the ported `forbiddenKeys` over the whole record; `house.test.ts` walks every interface key against `FORBIDDEN_KEY`. **Projections and sync** (`house-sync.ts`, pure; adapters `{toRow, fromRow, rename}` per wing): Table `HouseRecord.dishes` (projection-only: allergens, allergensCheckedAt, recipeSlug); Ledger `progress.bar` (`house` set only when non-empty so the eleven-key pin at `check-import.mjs:1118` stays); Codex `ST.cellar` (`grapes` joined on the row).
