## A. The House data model

### A.1 Storage

```
localStorage['oot-houses-v1']            HouseIndex   the list and the current pointer
localStorage['oot-house-v1.<houseId>']   House        one key per house, JSON text
localStorage['oot-house-undo-v1']        the outgoing projection rows of the last switch, best effort, 24 hours
```

localStorage on the one origin the three wings share, for the three verified reasons: the Codex reads `ST` synchronously at script load (`js/codex2.js:2`) and renders at boot; the inbox `oot-menu-desk-v1` already made that bend; the Table's IndexedDB `world-table`/`state` is a database the vanilla wings never open. A dot after the prefix, not `::`, so `oot-profiles.js key()` and the Pass scan never see a house as a profile key; neither key is in `BASES`, so `exportProfile` (which skips every `oot-` key at line 327) never carries a house and `importProfile` never writes one. The House travels only by its own pack file. The Table reads it in `hydrate()` and `onMount`, never in `load`.

Writes: `HOUSE_MAX_BYTES = 512 * 1024` per house; `HOUSES_WARN_BYTES = 1536 * 1024` across houses (a warning line on the switcher, never a refusal); every write goes through `writeHouse(house, storage)`, which serialises, measures and refuses whole with `{ ok: false, reason: 'too-big' | 'no-storage' | 'refused', said }`; every read is try/catch and never throws. The ORDER of every save is projection first, House second, so a refused House write never loses a wing record (the row is then newer than the house and the next `syncIn` adopts it). A refused House write surfaces through the wing's own quota banner: the Ledger's `storage-alarm.js` (its `store.degraded` flag) and the Codex's codex15 `ST_SAVE_BROKEN` path, each gaining one sentence naming the pack export as the way out; the Table prints the refusal under `HouseBar`. The undo slot is best effort: `switchTo` measures before writing it and a refused undo write never refuses the switch (the switch sentence then says "the previous list was not kept aside").

No write on load, anywhere: a device with rows and no index is an IMPLICIT house (A.6 rule 3), and the first House write a person causes mints it. The only House writes at boot are adoption writes into an index that already exists (a person made it), `absorbSession`'s precedent in `hydrate()`.

When each wing reads it: the Ledger inside the boot IIFE in `js/app.js` right after line 1049 (`progress.bar = normalizeBarRecords(progress.bar).bar;`), where `progress` is loaded; the Codex in `js/codex27.js` at script load, after `ST` exists and before `boot.js` renders; the Table inside `hydrate()` after `absorbSession`, in this order: `this.#ready = true`, then `syncIn` on the projection, then `#persist()` when the sync changed a row, and the whole sync skipped while `#blocked` (a blocked Table neither writes its projection nor writes the House from rows it could not read). All three add one `window.addEventListener('storage', ...)` for the two key shapes and re-run `syncIn` on it; the Ledger's listener honours `captureLiveInputs` (app.js 1002 to 1016) and defers the re-render while `state.menu.editing` or an import is busy; the Table's never runs while `#blocked`.

### A.3 Ids and minting

`mintId(prefix, taken, rand)` = prefix plus eight base36 characters; dishes `d-`, wines `w-`, cocktails `b-` (the wings' own mints kept per kind, so a House item and its projection row share one id and the Codex's `ST.q` keys `w-xxxxxxxx-gr` and `keyOwned`'s refusal keep holding); houses `h-`; tastings `t-`, lexicon `x-`, scenarios `s-`, mix-ups `m-`, must-knows `k-`. No id contains `|` or `:`.

### A.4 The pack file (`house-pack.ts`)

```ts
export const PACK_FORMAT = 'oot-house-pack'; export const PACK_VERSION = 1;
export interface PackFile { format: 'oot-house-pack'; version: 1; exportedAt: string; app: { from: 'table'|'ledger'|'codex'|'tools' }; house: House }
packFilename(house, now)   -> `house-${slug(house.name)}-${YYYY-MM-DD}.oothouse.json`
buildPack(house, from)     -> PackFile
readPack(text)             -> { ok: true, house, problems: [] } | { ok: false, said }
```

`readPack` parses, refuses a wrong `format` or a `version` above 1, caps every string (600 characters a prose field, 2,000 items a list), runs `normaliseHouse` then `validateHouse`, and never writes. `importPack(pack, choice, storage)` returns `{ ok, added: id, current: boolean, said }`: a pack whose `house.id` is not on the device is added as a new house and becomes current when the device had no index at all, or when its only house is a `began: 'hand'` house with zero items; otherwise it is added behind the current house. A pack whose id IS on the device is never written over silently: "Add as a new house" (default; re-minted under a new `h-` id, items keep theirs) or "Merge into {name}" (A.5), which ends on a count: "14 items added, 9 lines updated, 3 of yours kept because newer". Every import screen in every wing ends on one sentence with two chips: "{name} added. Open it now?" Open (`switchTo`) / Not now. When the device has rows and no index at the moment of an import, the implicit house is minted first as "My house" (`began: 'hand'`) so the person's rows are never swallowed by the pack; that is a write a person caused.

Import by file (`<input type=file accept=.json,application/json>`) or by address (`fetch(url, { cache: 'reload' })` on the press only; a relative address is accepted, and the Table accepts both `/shared/packs/...` and `/table/shared/packs/...`). The copy is the Ledger's link door's: "A file sent by message works everywhere; an address only when its host allows it." The importer prints the pack's `exportedAt` and offers "Fetch again" (the Table's route serves the stale copy first; the Codex worker gains a network-first branch for `/shared/packs/`, E.5).

### A.5 Merge (`house-merge.ts`, pure)

`mergeHouse(mine, theirs)`: per list by id; the item's plain fields travel whole with the newer `ts`, tie mine; every mark settles by `pickMark` copied word for word from `state.ts:628` (a person's mark beats hers whatever the stamps, then the newer `ts`, tie mine); `pairing` settles as one mark; `kept` unions on `ts|q`; a tombstone in either `removed` newer than the item's `ts` drops the item on both sides; house-level plain fields take the newer `lastWrite`'s; `sources` union by url; `menusReadOn` the later date; `build` the max per step. Symmetric and idempotent, both pinned. `mergeHouse` returns `{ house, counts: { added, updated, keptMine } }` for the sentence.

`syncIn(kind, rows, house, adapter)` and `syncOut(...)` take `adapter = { toRow(item, prevRow), fromRow(row), rename(row, newId) }`. The rules:

1. Twin by id: if `item.ts > row.ts` the row's shared fields take the item's; if `row.ts > item.ts` the reverse; equal, nothing. Marks settle per field by `pickMark`; `kept` unions. Written only when something changed.
2. 3. A row with no `house`, or with a `house` not on the device's index (a backup from another device): when an index with a current house exists, the row is adopted into it once and stamped (`absorbSession`'s precedent); when no index exists, the rows are the implicit house and nothing is written until a person's act mints it (the first `put` from a save, the first export, the first import, the first stepper step).
4. A row whose `house` is current and that has no item: if `house.removed[id]` is newer than `row.ts` the row leaves the projection; otherwise the row is added to the house.
5. `syncIn` REMOVES nothing without a tombstone; an empty house with a full projection adopts the rows, never the reverse. Removal travels only through the wing's own delete, each of which now also calls `OOT.house.remove(kind, id)`.

When it runs: at boot; on every projection save (`saveDish`, `saveBarRecord`, the Codex cellar save and `cellarAddMany` call `put(kind, row)` after their own save); on every House write from the Mine screens; on a `storage` event; on `switchTo`. ### E.5 The publish rule, per surface

Written once here, enforced by `check-stamps.mjs`, applied in every piece:

- The Ledger worker precaches `ASSETS` and never runtime-caches, so a change to a file in its `ASSETS` (`oot-house.js`, `oot-house-ui.js`, `oot-locks.js`, its own js) bumps `oot-ledger-vN`; `oot-maitre.js` and `oot-quotes.js` are fetched through (the HTTP cache's ten minutes is the only lag).

- The Table precaches nothing lazy; its `/shared/` route revalidates; a rebuild carries the new revisions.
- In the source repos, every piece's commit bumps `sw.js` `CACHE` (`ledger-v61` onward, `codex-v74` onward) and the touched files' `?v=`.
- The committed pack path carries its version: `shared/packs/brennans-new-orleans.v1.oothouse.json`; a new build is a new file name and a Codex bump.
